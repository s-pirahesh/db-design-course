ویژگی‌های View:

✅ مجازی: داده ذخیره نمی‌شه (Virtual) ✅ مبتنی بر Query: از SELECT ساخته می‌شه ✅ پویا: همیشه به‌روز (با جدول مبنا) ✅ نامدار: اسم داره (Named) ✅ محدود: فقط بخشی از داده

🎨 ساختار CREATE VIEW

: نحوه تعریف View با زبان SQL: 

CREATE VIEW view_name [(column_list)]
AS
    SELECT_statement
[WITH CHECK OPTION];

نکته : علامت [ ] به معنی اختیاری بودن است. اگر اسامی ستون‌های View با ستون‌های جدول اصلی یکسان باشد می‌توانیم ننویسیم.

مثال 2: View با WHERE - شهر خاص

: 

CREATE VIEW V2 (SCode, Status, City) AS
SELECT S#, Status, City
FROM S
WHERE (City <> 'C3') AND (Account > 100);

معنا: 

فقط تأمین‌کننده‌هایی که:
→ شهرشون C3 نباشه ✅
→ موجودی‌شون بیشتر از 100 باشه ✅

مثال 3: View با JOIN - چند جدول

: 

-- S: Supplier, P: Part, SP: Supply
CREATE VIEW V1 AS
SELECT S.S#, S.SName, P.P#, P.PName, SP.Qty
FROM S, P, SP
WHERE (S.S# = SP.S#) 
  AND (P.P# = SP.P#)
  AND (S.City = 'C2')
  AND (S.Account > 100);

مثال 4: View آماری - Aggregation

CREATE VIEW DeptStats AS
SELECT 
    Department,
    COUNT(*) AS EmpCount,
    AVG(Salary) AS AvgSalary,
    MAX(Salary) AS MaxSalary
FROM Employee
GROUP BY Department;

1️⃣ تأمین‌کننده اشتراک داده‌ها (Data Sharing)

چند کاربر از یک View استفاده می‌کنن:

کاربران دبیرخانه (10 نفر):
→ همه از ContactView استفاده می‌کنن ✅
→ هماهنگی داده ✅
→ یک منبع (Employee) ✅

2️⃣ مکانیزم اتوماتیک امنیت (Data Hidden)

: مکانیزم اتوماتیک امنیت پایگاه داده‌ها با پیاده‌سازی مفهوم داده نهان. 

-- حسابدار فقط این رو می‌بینه:
CREATE VIEW SalaryView AS
SELECT EmpID, Name, Salary
FROM Employee;

-- نمی‌تونه Phone و Address ببینه! ✅
-- نمی‌تونه جدول Employee ببینه! ✅

3️⃣ تأمین‌کننده استقلال داده‌ای

: تأمین‌کننده استقلال داده‌ای (Data Independency) که از مزایای مهم تکنولوژی دیتابیس است. 

مثال:
→ جدول Employee تغییر می‌کنه (ستون جدید)
→ View‌ها تحت تأثیر قرار نمی‌گیرن ✅

ALTER TABLE Employee ADD Email NVARCHAR(100);

→ SalaryView همچنان کار می‌کنه ✅
→ برنامه‌های کاربر نیازی به تغییر ندارن ✅

4️⃣ تسهیل‌کننده برنامه‌سازی

: تسهیل‌کننده برنامه‌سازی است چون کاربر با یک ساختار محدود کار می‌نماید و نه با جداول بزرگ. 

جدول Employee: 20 ستون ❌
View SalaryView: 3 ستون ✅

→ برنامه‌نویس راحت‌تر کار می‌کنه ✅
→ خطای کمتر ✅

2️⃣ فزون‌کاری (Overhead)

: فزون‌کاری یا Overhead ناشی از لزوم انجام تبادلات (نگاشت‌ها). 

Query روی View:
→ تبدیل به Query روی جدول مبنا ✅
→ زمان اضافی ❌
→ کندی ❌

دلایل دیگر بروز Overhead در DBMS‌ها ():

  1. لزوم انجام تبدیلات (Mapping)
  2. اعمال محدودیت‌های جامعیتی
  3. اعمال ضوابط امنیتی

شرط 1: روی یک جدول مبنا

: این دید باید روی یک جدول مبنا و یک دید قابل به‌هنگام‌سازی تعریف شده باشد. 

-- ✅ Updatable
CREATE VIEW V1 AS
SELECT EmpID, Name, Salary
FROM Employee;

-- ❌ NOT Updatable (دو جدول!)
CREATE VIEW V2 AS
SELECT E.EmpID, E.Name, D.DeptName
FROM Employee E, Department D
WHERE E.DeptID = D.DeptID;

استثنا : اگر ارتباط ۲ جدول از طریق کلید اصلی باشد، View که از ارتباط این ۲ جدول به وجود می‌آید قابل به‌هنگام‌سازی است. 

-- ✅ Updatable (اگر JOIN روی PK باشه)
CREATE VIEW V4 AS
SELECT T1.*, T2.*
FROM T1 JOIN T2 ON T1.A1 = T2.B1;
-- شرط: A1 و B1 کلید اصلی باشن

شرط 2: هر سطر متناظر با یک سطر جدول

: هر سطر دید باید متناظر با یک سطر جدول مبنا باشد (اگر کلید داشته باشد این شرط می‌تواند برقرار باشد). 

-- ✅ Updatable (کلید داره)
CREATE VIEW V1 AS
SELECT EmpID, Name, Salary
FROM Employee;

-- ❌ NOT Updatable (DISTINCT)
CREATE VIEW V2 AS
SELECT DISTINCT Department
FROM Employee;
-- هر Department چند بار تکرار می‌شه!

شرط 3: هر ستون متناظر با یک ستون مشخص

: هر ستون باید متناظر با یک ستون مشخص از جدول مبنا باشد. بنابر این اگر در یک دید ستون مجازی داشته باشیم (دید آماری باشد) این دید قابل به‌هنگام‌سازی نمی‌باشد. 

-- ❌ NOT Updatable (ستون مجازی!)
CREATE VIEW DeptStats AS
SELECT 
    Department,
    COUNT(*) AS EmpCount,  -- ستون مجازی!
    AVG(Salary) AS AvgSalary  -- ستون مجازی!
FROM Employee
GROUP BY Department;

-- نمی‌شه INSERT کرد چون EmpCount مجازیه!

شرط 4 و 5: بدون GROUP BY و HAVING

: اگر در یک دید، GROUP BY داشته باشیم، آن دید قابل به‌هنگام‌سازی نمی‌باشد. اگر در یک دید، HAVING داشته باشیم، آن دید قابل به‌هنگام‌سازی نمی‌باشد. 

-- ❌ NOT Updatable (GROUP BY)
CREATE VIEW V1 AS
SELECT Department, AVG(Salary) AS AvgSal
FROM Employee
GROUP BY Department;

نکته : HAVING فقط برای ۶ دستور به‌کار می‌رود: COUNT, AVG, SUM, MAX, MIN, COUNT(DISTINCT).

شرط 7: ستون‌های NOT NULL

: از ستون‌های NOT NULL در جدول چند تا را نداشته باشیم INSERT نمی‌شود انجام داد ولی UPDATE و DELETE می‌توان انجام داد. 

-- جدول مبنا
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,      -- NOT NULL
    Name NVARCHAR(50) NOT NULL, -- NOT NULL
    Salary DECIMAL(12,2)
);

-- ❌ View برای INSERT
CREATE VIEW V1 AS
SELECT EmpID, Salary  -- Name نداره!
FROM Employee;

-- نمی‌شه INSERT (Name ضروریه!) ❌
INSERT INTO V1 VALUES (130, 40000000);

-- ✅ می‌شه UPDATE
UPDATE V1 SET Salary = 45000000 WHERE EmpID = 100;

-- ✅ می‌شه DELETE
DELETE FROM V1 WHERE EmpID = 100;

مثال : 

-- تعریف View
CREATE VIEW V2 (SCode, Status, City) AS
SELECT S#, Status, City
FROM S
WHERE (City <> 'C3') AND (Account > 100);

-- Query در سطح خارجی
SELECT City
FROM V2
WHERE Status > 100;

-- تبدیل به Query در سطح ادراکی (DBMS)
SELECT City
FROM S
WHERE (City <> 'C3') 
  AND (Account > 100) 
  AND (Status > 100);

کدام View قابل به‌هنگام‌سازی نیست؟ 

الف) CREATE VIEW V1 AS SELECT EmpID, Name FROM Employee;

د) CREATE VIEW V4 AS SELECT * FROM Employee;
