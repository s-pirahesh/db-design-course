👤 کاربر 2 (مدیر): می‌خواد گزارش‌های کلی ببینه

📖 معماری ANSI/SPARC

تعریف: معماری استاندارد ANSI/SPARC پایگاه داده را به سه سطح (سه شِما) تقسیم می‌كند:

  1. سطح خارجی (External Level / EDS): N دید مختلف برای كاربران
  2. سطح ادراكی (Conceptual Level / CDS): یك شِمای منطقی كامل از پایگاه
  3. سطح داخلی (Internal Level / IDS): یك شِمای داخلی كه DBMS می‌داند چگونه داده‌ها در فایل‌ها سازماندهی شده‌اند

نكته مهم: ذخیره‌سازی فیزیكی روی دیسك (Physical Storage) زیر سطح داخلی قرار دارد و توسط سیستم‌عامل مدیریت می‌شود؛ این بخش جزو سه سطح ANSI/SPARC نیست ولی برای درك بهتر در نمودار زیر نشان داده شده است.

نکته کلیدی: این معماری سه‌سطحی است که سطوح آن‌ها با هم مستقل هستند. هدف این جدایی، تأمین استقلال داده‌ای (Data Independence) است كه در بخش ۳-۴ توضیح داده می‌شود.

🎯 سه سطح معماری ANSI/SPARC (به‌علاوه ذخیره‌سازی فیزیكی)

در ادامه هر سه سطح ANSI/SPARC را به‌طور دقیق توضیح می‌دهیم، و در پایان نیز برای روشن شدن مرز بین سطح داخلی DBMS و ذخیره‌سازی فیزیكی OS بخشی جداگانه آورده شده است.

1️⃣ سطح خارجی (External Level / EDS)

تعریف: دید خارجی: دید کاربر خاص است نسبت به داده‌های ذخیره‌شده.

ویژگی‌ها:

✅ تعداد: N دید خارجی (هر کاربر یک دید) ✅ محتوا: بخشی از داده‌های کلی ✅ هدف:

  • ساده‌سازی (Simplification)
  • امنیت (Security) - مخفی‌سازی داده
  • اشتراک داده (Data Sharing)

✅ زبان: HL (Host Language) + DSL (SQL)

مثال: 

-- View برای حسابدار (فقط حقوق)
CREATE VIEW SalaryView AS
SELECT EmpID, Name, Salary
FROM Employee;

-- View برای مدیر (گزارش کلی)
CREATE VIEW ManagerReport AS
SELECT DeptID, COUNT(*) AS EmpCount, AVG(Salary) AS AvgSalary
FROM Employee
GROUP BY DeptID;

2️⃣ سطح ادراکی (Conceptual Level / CDS)

تعریف: دید ادراکی (Conceptual): دید طراح است نسبت به داده‌های ذخیره‌شده (یعنی آن‌گونه که طراح داده‌ها را می‌بیند).

این دید مبتنی است بر یک DS مشخص می‌تواند RDS, HDS یا NDS باشد.

ویژگی‌ها:

✅ تعداد: فقط 1 دید ادراکی ✅ محتوا: تمام داده‌های سیستم ✅ مستقل: از ذخیره‌سازی فیزیکی ✅ توصیف: با DSL (Data Schema Language)

  • DD (Data Definition)
  • DM (Data Manipulation)
  • DC (Data Control)

مثال (SQL): 

-- جداول کامل سیستم
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Name VARCHAR(100),
    Salary DECIMAL(10,2),
    DeptID INT,
    FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
);

CREATE TABLE Department (
    DeptID INT PRIMARY KEY,
    DeptName VARCHAR(100),
    ManagerID INT
);

-- همه موجودیت‌ها و ارتباطات ✅

نکته مهم: این شما به سیستم داده می‌شود و سیستم آن را در کاتالوگ و بر اساس ساختار داده‌ای خود نگه‌داری می‌کند.

3️⃣ سطح داخلی (Internal Level / IDS)

تعریف: دید داخلی: دید DBMS و طراح آن است از داده‌های ذخیره‌شده. که در این دید مبتنی بر چند فایل است که داده‌ها به صورت داده‌های منطقی است.

✅ تعداد: فقط 1 دید داخلی ✅ محتوا:

  • فرمت رکوردها
  • ساختار فایل‌ها (Heap, Index, ...)
  • استراتژی دستیابی
  • ایندکس‌ها

✅ نگاشت: جداول → فایل‌های منطقی

- چه چیزهایی DBMS می‌داند:

✅ می‌داند:

  • فرمت رکوردهای فایل
  • ساختار فایل (Indexed, Heap)
  • استراتژی فایل
  • حجم داده‌ای فایل
  • کلید اصلی فایل
  • اندازه گسترش فایل
  • فیلدهای جستجو

❌ نمی‌داند:

  • طرز نشست فیزیکی فایل‌ها (روی شیارها)
  • محل دو رکورد همجوار (Locality)
  • اندازه فیزیکی بلاک‌ها (NTFS, FAT32)
  • تعداد بافرهای I/O

مثال: 

-- ایجاد ایندکس برای جستجوی سریع
CREATE INDEX idx_emp_dept ON Employee(DeptID);
CREATE INDEX idx_emp_salary ON Employee(Salary);

-- تعریف فضای ذخیره‌سازی
CREATE TABLESPACE emp_data
DATAFILE '/path/to/emp_data.dbf' SIZE 100M;

نکته: به ازای N تا Table می‌توان M تا فایل داشت: یا 1:1 یا 1:N. در SQL پیش‌فرض 1:N است.

🗄️ ذخیره‌سازی فیزیكی (Physical Storage / PDS) — خارج از ANSI/SPARC

توجه: این سطح جزو سه سطح ANSI/SPARC نیست. هدف از آوردن آن، روشن‌كردن مرز بین چیزی است كه DBMS می‌داند (سطح داخلی) و چیزی كه سیستم‌عامل مدیریت می‌كند (ذخیره‌سازی فیزیكی).

تعریف: PDS (Physical Data Structure): ساختار بایت‌ها روی رسانه فیزیكی (دیسك سخت، SSD، …).

ویژگی‌ها:

✅ محتوا:

  • فایل‌های فیزیکی روی دیسک
  • بلاک‌ها (Blocks)
  • شیارها (Sectors)
  • سیلندرها (Cylinders)

✅ مدیریت: توسط OS (سیستم‌عامل)
✅ نامرئی: هم برای كاربر و هم برای سطح داخلی DBMS (DBMS فقط فایل‌های منطقی را می‌بیند، نه بلاك‌ها)

نگاشت سوم (Internal → Physical) كه گاهی در منابع دیده می‌شود، نگاشتی خارج از قلمرو DBMS است و توسط سیستم‌عامل/سخت‌افزار (مدیریت فایل و درایور دیسك) انجام می‌شود.

1️⃣ استقلال داده‌ای (Data Independence)

تعریف: مفهوم استقلال داده‌ای: مصونیت برنامه‌های کاربردی (کاربران سطح خارجی) در قبال تغییراتی که در سطوح زیرین معماری پایگاه پدید می‌آید. 

الف) استقلال فیزیکی:
→ تغییر فایل‌ها، ایندکس‌ها
→ برنامه‌های کاربر تحت تأثیر قرار نمی‌گیرن ✅

مثال:
- اضافه کردن ایندکس جدید
- تغییر ساختار فایل (Heap → B+Tree)
- انتقال به دیسک دیگر

ب) استقلال منطقی:
→ تغییر جداول (اضافه/حذف ستون)
→ View‌ها تحت تأثیر قرار نمی‌گیرن ✅

مثال:
- اضافه کردن ستون جدید به جدول
- تقسیم یک جدول به دو جدول

2️⃣ امنیت (Security)

کاربر حسابدار:
→ فقط View حقوق ✅
→ نمی‌تونه جدول کامل ببینه ❌

→ امنیت داده (Data Hiding) ✅

3️⃣ ساده‌سازی (Simplification)

کاربر:
→ با جدول 100 ستونی کار نمی‌کنه ❌
→ با View ساده 5 ستونی کار می‌کنه ✅

→ کاهش پیچیدگی ✅

4️⃣ اشتراک داده (Data Sharing)

10 کاربر مختلف:
→ 10 View مختلف
→ همه از یک منبع (Conceptual) ✅

→ هماهنگی داده ✅

✍️ تمرینات بخش ۳.۲

تمرین 1 (تشریحی):

شرکت:

  • کاربر 1 (حسابدار): فقط حقوق کارمندان
  • کاربر 2 (مدیر): گزارش‌های آماری
  • کاربر 3 (منابع انسانی): اطلاعات کامل

طراحی کنید:

  • سطح ادراکی (جداول)
  • سطح خارجی (3 View)
  • کدوم View چه ستون‌هایی داره؟

تمرین 2 (تستی):

کدام گزینه نادرست است؟

الف) سطح ادراکی فقط یکی است ب) سطح خارجی می‌تواند چند تا باشد ج) تغییر سطح فیزیکی روی سطح خارجی تأثیر می‌گذارد د) View بخشی از جدول را نشان می‌دهد

تمرین 3 (استقلال داده):

تغییرات زیر روی چه سطوحی تأثیر می‌ذارن؟

الف) اضافه کردن ایندکس به جدول Employee ب) اضافه کردن ستون "Email" به جدول Employee ج) تغییر دیسک ذخیره‌سازی د) تقسیم جدول Employee به دو جدول

تمرین 4 (طراحی):

دانشگاه:

  • Conceptual: Student(ID, Name, Major, GPA, Phone)

ایجاد کنید:

  • View1 (دبیرخانه): ID, Name, Major
  • View2 (استاد): ID, Name, GPA
  • View3 (مخابرات): ID, Name, Phone

چرا این View‌ها مفیدن؟

تمرین 5 (تحلیلی):

مزایای معماری سه‌لایه رو با مثال کامل توضیح بده:

  • استقلال فیزیکی
  • استقلال منطقی
  • امنیت
  • ساده‌سازی

تمرین 6 (پیشرفته):

اگر معماری سه‌لایه نداشتیم چه مشکلاتی پیش می‌اومد؟ هر کاربر مستقیم با فایل‌های فیزیکی کار می‌کرد. 5 مشکل اساسی رو بنویس.
