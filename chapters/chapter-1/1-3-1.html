🎯 مقدمه تعاملی

خوب دانشجوی عزیز، تا اینجا یاد گرفتیم که DBMS چیه و چه مشکلاتی رو حل می‌کنه. حالا می‌خوایم ببینیم چطور یک سیستم پایگاه داده رو پیاده‌سازی کنیم؟

فرض کن می‌خوای سیستم دانشگاه رو بسازی. چند سوال مهم پیش میاد:

  • پایگاه داده رو کجا بذاریم؟ 🤔
  • کاربران چطور دسترسی پیدا می‌کنن؟
  • چند سرور لازم داریم؟
  • وظایف رو چطور تقسیم کنیم؟

جواب این سوالات به معماری سیستم بستگی داره!

🏢 معماری متمرکز (Centralized Architecture)

تعریف : اجزای معماری متمرکز:

  1. پیکر بندی نرم‌افزاری - سخت‌افزاری: رایانه‌ای که در آن OS (سیستم عامل) نصب شده باشد
  2. یک نرم افزار DBMS
  3. مجموعه‌ای از برنامه‌های کاربردی
  4. حداقل یک کاربر

↓

2. محدودیت مقیاس‌پذیری (Scalability)

کاربران بیشتر می‌شن:
100 کاربر → سرور 1: OK ✅
1,000 کاربر → سرور 1: کند شد 🐌
10,000 کاربر → سرور 1: خیلی کند 🐢
100,000 کاربر → سرور 1: از کار افتاد ❌

راه حل؟ باید سرور بزرگ‌تر بخری! (گران!)

3. عملکرد شبکه

sequenceDiagram
    participant U as کاربر راه دور

مشکل: کاربران دور از سرور مرکزی، تاخیر زیاد دارن!

4. هزینه بالا (برای سازمان‌های بزرگ)

برای 100,000 کاربر:
→ نیاز به سرور بسیار قوی (خیلی گران!)
→ DB Machine خاص $$$
→ RAM زیاد
→ CPU قدرتمند

تقسیم وظایف

لایه 1: کلاینت (Front-end) 

وظایف:
✅ نمایش UI
✅ دریافت ورودی کاربر
✅ ارسال درخواست به سرور برنامه

مثال:
- مرورگر وب
- برنامه Desktop
- اپلیکیشن موبایل

لایه 2: سرور برنامه (Middle-tier) 

وظایف:
✅ پردازش منطق کسب و کار
✅ اعتبارسنجی داده‌ها
✅ ارتباط با DB
✅ مدیریت Session

مثال:
- Web Server (Apache, IIS)
- Application Server (Tomcat, Node.js)

لایه 3: سرور دیتابیس (Back-end) 

وظایف:
✅ ذخیره داده‌ها
✅ اجرای Query
✅ مدیریت Transaction
✅ امنیت

مثال:
- SQL Server
- Oracle
- PostgreSQL

✅ مزایای معماری کلاینت/سرور

1. صرفه‌جویی در سخت‌افزار

قبل (متمرکز):
- سرور بسیار قوی: $100,000
- کلاینت‌های ساده (Terminal): $500 × 100 = $50,000
جمع: $150,000

بعد (C/S):
- سرور متوسط: $30,000
- کلاینت‌های متوسط (PC): $1,000 × 100 = $100,000
جمع: $130,000

صرفه‌جویی: $20,000 ✅

2. امنیت بالاتر

کاربران به DB دسترسی مستقیم ندارن!
→ فقط از طریق سرور برنامه ✅
→ راحت‌تر کنترل می‌شه ✅

3. انعطاف‌پذیری

می‌خوای کاربر اضافه کنی؟
→ فقط یک PC جدید ✅

می‌خوای سرور رو تغییر بدی؟
→ کلاینت‌ها نیازی به تغییر ندارن ✅

4. مقیاس‌پذیری

کاربران زیاد شدن:
→ سرور برنامه اضافه کن
→ Load Balancer بذار وسط
→ کاربران به چند سرور متصل می‌شن ✅

5. اطمینان عملیاتی بیشتر

: "اطمینان عملیاتی بیشتر از نظر کنترل عملیات Application‌ها" 

همه منطق کسب و کار در سرور:
→ یک‌بار تغییر می‌دی
→ برای همه کاربران اعمال می‌شه ✅

مثال: 

قانون جدید: "حداکثر 20 واحد ثبت‌نام"

C/S: فقط سرور برنامه رو تغییر بده ✅
متمرکز: همه کلاینت‌ها رو باید Update کنی ❌

❌ معایب معماری کلاینت/سرور

1. پیچیدگی بیشتر

باید مدیریت کنی:
- کلاینت‌ها (صدها!)
- سرور برنامه
- سرور DB
- شبکه

→ نیاز به تیم بزرگ‌تر

2. وابستگی به شبکه

اگر شبکه قطع شه:
→ کلاینت‌ها نمی‌تونن کار کنن ❌

3. مشکل همگن بودن (Multi C/Multi S)

باید همه سرورها یکسان باشن:
→ محدودیت در انتخاب
→ اگر یکی متفاوت باشه، مشکل! ❌

📊 مقایسه جامع: متمرکز vs کلاینت/سرور

✍️ تمرینات بخش ۱.۳.۱

تمرین 1 (تشریحی):

مزایا و معایب معماری متمرکز را با یک مثال واقعی از زندگی خودتان (غیر از دانشگاه) توضیح دهید.

تمرین 2 (تستی):

کدام گزینه نادرست است؟

الف) در معماری متمرکز، SPOF یک مشکل جدی است ب) در C/S، کلاینت مستقیماً به DB دسترسی دارد ج) معماری 3-لایه محبوب‌ترین نوع C/S است د) در Multi C/Multi S، سرورها باید همگن باشند

تمرین 3 (طراحی):

یک کتابخانه دارد که:

  • 5 کارمند
  • 50,000 کتاب
  • 10,000 عضو

کدام معماری مناسب‌تر است؟ چرا؟

  • متمرکز؟
  • کلاینت/سرور (چند کلاینت / یک سرور)؟

طراحی کامل ارائه دهید.

تمرین 4 (محاسباتی):

یک شرکت می‌خواهد سیستم CRM بسازد:

  • 500 کارمند
  • 100,000 مشتری
  • 1,000,000 تراکنش در روز

هزینه‌ها:

  • سرور قوی: $50,000
  • سرور متوسط: $20,000
  • PC: $1,000

محاسبه کنید:

  1. هزینه معماری متمرکز
  2. هزینه معماری C/S (1 سرور DB + 1 سرور App)
  3. کدوم مقرون به صرفه‌تر است؟

تمرین 5 (سناریو):

شما مدیر IT یک بیمارستان هستید. سیستم فعلی متمرکز است و مشکلات زیر دارد:

  • سرور گاهی down می‌شه → کل سیستم از کار می‌افته
  • دکترها از کلینیک‌های دور نمی‌تونن سریع دسترسی داشته باشن

سوالات:

  • چه معماری پیشنهاد می‌کنید؟
  • چرا این معماری بهتر است؟
  • چه چالش‌هایی در migration وجود دارد؟

تمرین 6 (تحلیلی):

چرا در Multi C/Multi S، سرورها باید همگن باشند؟ اگر ناهمگن باشند (مثلاً SQL Server + Oracle)، چه مشکلاتی پیش می‌آید؟ 3 مشکل مهم بیاورید.
