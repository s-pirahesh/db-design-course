1️⃣ کلید فوق (Super Key - SK)

تعریف

کلید در RM تعریف ریاضی دارد.

H = مجموعه هدینگ رابطه R 

R(A₁, A₂, ..., Aₙ)
H = {A₁, A₂, ..., Aₙ}

هر زیرمجموعه S ⊆ H که خاصیت یکتایی (Uniqueness) را داشته باشد، کلید SK است.

تعریف ریاضی SK

اگر tᵢ و tⱼ دو تاپل دلخواه از رابطه R باشند: 

(tᵢ ∈ R) ∧ (tⱼ ∈ R) ∧ (tᵢ ≠ tⱼ)  →  tᵢ[S] ≠ tⱼ[S]

به زبان ساده: اگر دو تاپل متفاوت باشن، مقادیرشون روی S هم متفاوت باشه!

مثال - Super Key

Student(StudentID, Name, LastName, Major, BirthYear)

داده نمونه:
+-----+------+----------+------+-----------+
|  ID | Name | LastName | Major| BirthYear |
+-----+------+----------+------+-----------+
| 100 | Ali  | Rezaei   | CS   | 1380      |
| 110 | Sara | Ahmadi   | Math | 1381      |
| 120 | Ali  | Karimi   | CS   | 1380      |
+-----+------+----------+------+-----------+

کدوم زیرمجموعه‌ها SK هستن؟

✅ SK ها:

  1. {StudentID} ← یکتاست! ✅
  2. {StudentID, Name} ← یکتاست (ID کافیه!) ✅
  3. {StudentID, Name, LastName} ← یکتاست ✅
  4. {Name, LastName, BirthYear} ← یکتاست؟ بررسی کنیم!
  5. {StudentID, Major} ← یکتاست ✅
  6. ... (همه ترکیبات که شامل StudentID)

❌ Non-SK ها:

  1. {Name} ← تکراری! (دو Ali داریم) ❌
  2. {Major} ← تکراری! (دو CS داریم) ❌
  3. {Name, Major} ← تکراری! (Ali + CS تکراریه) ❌

چک کردن: 

{Name, LastName, BirthYear} SK است؟

تاپل 1: (Ali, Rezaei, 1380)
تاپل 2: (Sara, Ahmadi, 1381)  → متفاوت ✅
تاپل 3: (Ali, Karimi, 1380)  → متفاوت ✅

هیچ دو تاپل یکسانی نداریم → SK است! ✅

سؤال مهم: حداقل و حداکثر SK

سؤال: هر رابطه حداقل و حداکثر چند تا می‌تواند کلید SK داشته باشد؟

توضیح:

حداقل SK = 1

بدترین حالت: → هیچ ترکیبی از صفت‌ها منحصربه‌فرد نباشه → فقط همه صفت‌ها با هم یکتایی دارن → SK = H (خود مجموعه هدینگ)

مثال: R(Name, Age, City) → Name تکراری → Age تکراری → City تکراری → (Name, Age) تکراری → (Name, City) تکراری → فقط (Name, Age, City) یکتاست!

→ SK = {Name, Age, City} = H

به رابطه‌ای که فقط یک کلید دارد، رابطه تمام‌کلید می‌گویند.

حداکثر SK = 2ⁿ - 1

بهترین حالت: → همه زیرمجموعه‌ها (به جز ∅) یکتایی دارن! → تعداد زیرمجموعه‌های H = 2ⁿ → حذف ∅ → 2ⁿ - 1

مثال: R(A, B, C) (n=3) → 2³ - 1 = 7 زیرمجموعه

همه SK هستن:

  1. {A}
  2. {B}
  3. {C}
  4. {A, B}
  5. {A, C}
  6. {B, C}
  7. {A, B, C}

2️⃣ کلید کاندید (Candidate Key - CK)

تعریف

هر زیرمجموعه C ⊆ H که دو خاصیت زیر را داشته باشد، کلید CK است: 

mindmap
  root((Candidate Key
CK))
    1 Uniqueness
      یکتایی مقدار
      SK باشد
      دو تاپل یکسان نداشته باشیم
    2 Irreducibility
      کاهش ناپذیری
      Minimal
      حذف هر صفت یکتایی بره

1. یکتایی مقدار (Uniqueness): → یعنی SK باشد!

2. کاهش‌ناپذیری (Irreducibility): صفت C را کاهش‌ناپذیر گوییم هرگاه هیچ زیرمجموعه‌ای از آن یکتایی مقدار نداشته باشد. 

به زبان ساده:
CK = SK + Minimal (کمینه)

اگر از CK یک صفت کم کنیم:
→ یکتایی از دست می‌ره! ❌

مثال - کاهش‌ناپذیری

Student(StudentID, Name, LastName)

SK ها:
1. {StudentID}  ✅
2. {StudentID, Name}  ✅
3. {StudentID, LastName}  ✅
4. {StudentID, Name, LastName}  ✅
5. {Name, LastName}  ✅ (فرض: یکتاست)

کدوم CK هستن؟

بررسی 1: {StudentID}
→ کاهش‌پذیر؟ نه! (تک‌صفتی است)
→ CK ✅

بررسی 2: {StudentID, Name}
→ کاهش‌پذیر؟ بله! چون:
  - حذف Name → {StudentID} که SK است!
→ CK ❌ (کاهش‌پذیر!)

بررسی 3: {Name, LastName}
→ کاهش‌پذیر؟ بررسی:
  - حذف Name → {LastName} که SK نیست! ✅
  - حذف LastName → {Name} که SK نیست! ✅
→ CK ✅ (کاهش‌ناپذیر!)

نتیجه:
CK ها: {StudentID}, {Name, LastName}

مثال پیچیده‌تر

Student(StudentID, Name, LastName, BirthYear, BirthCity, NationalID)

SK ها:
1. {StudentID}
2. {NationalID}
3. {Name, LastName, BirthYear, BirthCity}
4. {StudentID, Name}
5. {StudentID, NationalID}
6. ... (خیلی زیاد!)

کدوم CK هستن؟

✅ CK1 = {StudentID}
→ تک‌صفتی → کاهش‌ناپذیر ✅

✅ CK2 = {NationalID}
→ تک‌صفتی → کاهش‌ناپذیر ✅

✅ CK3 = {Name, LastName, BirthYear, BirthCity}
→ بررسی:
  - حذف Name → باقی SK نیست ✅
  - حذف LastName → باقی SK نیست ✅
  - حذف BirthYear → باقی SK نیست ✅
  - حذف BirthCity → باقی SK نیست ✅
→ کاهش‌ناپذیر → CK ✅

❌ {StudentID, Name} → CK نیست!
→ چون StudentID به تنهایی SK است!

نکته: هر کدام را حذف نموديم، بايد بقيه منحصربه‌فرد نباشند. 

مثال:
تركيب (سال تولد، محل تولد، شماره شناسنامه)

بررسی کاهش‌ناپذیری:
→ حذف سال تولد → (محل تولد، شماره شناسنامه) یکتا نیست ✅
→ حذف محل تولد → (سال تولد، شماره شناسنامه) یکتا نیست ✅
→ حذف شماره شناسنامه → (سال تولد، محل تولد) یکتا نیست ✅

→ تجزیه‌ناپذیر است → CK است! ✅

سؤال: حداقل و حداکثر CK

سؤال: هر رابطه حداقل و حداکثر چند تا کلید CK دارد؟

حداقل CK = 1 → خود H (رابطه تمام‌کلید)

مثال: Enrollment(StudentID, CourseID, Semester, Grade) → فقط CK = {StudentID, CourseID, Semester} → تعداد CK = 1

حداکثر CK = n → اگر n صفت داشته باشیم → هر صفت به تنهایی CK باشد

مثال: R(NationalID, PassportID, StudentID) → هر کدام تک‌صفتی و یکتا → CK1 = {NationalID} → CK2 = {PassportID} → CK3 = {StudentID} → تعداد CK = 3 = n

رابطه تمام‌کلید

تعریف: رابطه‌ای که CK آن برابر مجموعه عنوانش (H) باشد. 

-- مثال رابطه تمام‌کلید
Enrollment(StudentID, CourseID, Semester, Grade)

-- CK = {StudentID, CourseID, Semester}
-- CK = H (همه صفات!)

-- چون:
→ StudentID به تنهایی یکتا نیست (یک دانشجو چند درس)
→ CourseID به تنهایی یکتا نیست (یک درس چند دانشجو)
→ Semester به تنهایی یکتا نیست (یک ترم چند ثبت‌نام)
→ فقط (StudentID, CourseID, Semester) یکتاست! ✅

ویژگی مهم: چنین رابطه‌ای حداقل در BCNF می‌باشد.

🎯 نقش CK در مدل رابطه‌ای

امکان Addressing (ارجاع) یا Referring به یک تاپل در رابطه. 

معنا:
اگر در عملیاتی (مثل بازیابی) بر حسب یک مقدار CK جستجو کنیم:
→ پاسخ در صورت وجود، یک تک‌تاپل است! ✅

مثال: 

Student(StudentID, Name, Major, GPA)
-- CK = {StudentID}

-- جستجو با CK:
SELECT * FROM Student WHERE StudentID = 100;
→ حداکثر 1 تاپل! ✅

-- جستجو بدون CK:
SELECT * FROM Student WHERE Major = 'CS';
→ ممکنه N تاپل! ⚠️

بنابراین کلید CK تضمین‌کننده عمل تک‌تاپلی است.

3️⃣ کلید اصلی (Primary Key - PK)

تعریف

کلید اصلی یکی از کلیدهای کاندید است. 

PK ∈ {CK₁, CK₂, ..., CKₙ}

ضابطه انتخاب PK

چطور از بین CK‌ها، PK رو انتخاب کنیم؟

2 معیار اصلی:

  1. از لحاظ طول، کمتر باشد

→ ترجیحاً تک‌صفتی → یا حداقل تعداد صفت

  1. در محیط، شناخته‌شده‌تر باشد

→ مثلاً: StudentID بهتر از (Name, BirthYear) → چون همه با ID دانشجو آشنایی دارن!

مثال: 

Student(StudentID, Name, LastName, NationalID, BirthYear)

CK ها:
1. {StudentID}  → طول = 1 ✅
2. {NationalID}  → طول = 1 ✅
3. {Name, LastName, BirthYear}  → طول = 3 ❌

کدوم رو انتخاب کنیم؟

{StudentID} یا {NationalID}؟

در محیط دانشگاه:
→ StudentID شناخته‌شده‌تر است! ✅

انتخاب:
PK = {StudentID}  ✅
AK = {NationalID}, {Name, LastName, BirthYear}

چرا اصلاً باید یکی از CK‌ها رو PK کنیم؟

1. دلیل تاریخی: در دهه ۷۰ استفاده می‌شد و مفهوم PK رایج بود.

2. در تمامی DBMS‌ها تعریف شده است: 

CREATE TABLE Student (
    StudentID INT PRIMARY KEY,  -- Index اتوماتیک! ✅
    Name VARCHAR(50),
    ...
);

-- DBMS اتوماتیک:
-- 1. Index روی StudentID می‌سازه
-- 2. یکتایی چک می‌کنه
-- 3. Null نمی‌ذاره

3. کلید کاندید می‌تواند Null باشد، ولی کلید اصلی نمی‌تواند Null باشد: 

-- CK می‌تونه Null باشه:
CREATE TABLE Student (
    StudentID INT UNIQUE,  -- CK, می‌تونه Null باشه
    Name VARCHAR(50)
);

INSERT INTO Student VALUES (NULL, 'Ali');  -- ✅ مجاز!

-- PK نمی‌تونه Null باشه:
CREATE TABLE Student (
    StudentID INT PRIMARY KEY,  -- PK, نمی‌تونه Null باشه
    Name VARCHAR(50)
);

INSERT INTO Student VALUES (NULL, 'Ali');  -- ❌ خطا!

5️⃣ کلید خارجی (Foreign Key - FK)

تعریف نادقیق

ستون C₁ در جدول T₂ کلید خارجی است اگر در جدول T₁ کلید اصلی باشد. 

خیلی ساده:
→ ستونی که به جدول دیگه اشاره می‌کنه!

مثال ساده: 

Department:
┌─────┬────────────┐
│ D#  │ DeptName   │  ← PK
├─────┼────────────┤
│ 10  │ CS         │
│ 20  │ Math       │
└─────┴────────────┘

Employee:
┌─────┬────────┬─────┐
│ E#  │ Name   │ D#  │  ← FK (اشاره به Department.D#)
├─────┼────────┼─────┤
│ 100 │ Ali    │ 10  │
│ 110 │ Sara   │ 20  │
│ 120 │ Reza   │ 10  │
└─────┴────────┴─────┘

تعریف دقیق

صفت A₁ از رابطه R₂، در رابطه R₂ کلید خارجی است اگر:

  • در رابطه R₁ (می‌تواند متناظر با R₂ باشد) کلید کاندید باشد

زیر صفت خارجی نقطه‌چین می‌کشیم. 

R₁(A, B, C)  ← PK or CK
R₂(X, Y, A)  ← FK (اشاره به R₁.A)
        ----

فرمول: 

FK در R₂ → CK در R₁

هر صفت هم‌نام، هم‌دامنه و هم‌معنا می‌توانند عامل ارتباطی بین دو رابطه باشند.

مثال کامل FK

-- رابطه 1: Department (موجودیت قوی)
CREATE TABLE Department (
    DeptID INT PRIMARY KEY,
    DeptName VARCHAR(50)
);

-- رابطه 2: Employee (موجودیت قوی)
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    EmpName VARCHAR(50),
    DeptID INT,  -- کلید خارجی!
    FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
);

-- نماد:
Department(DeptID, DeptName)
           ------

Employee(EmpID, EmpName, DeptID)
         -----           ......
                           ↑
                      کلید خارجی (FK)

حالت خاص: FK به خودش

یک رابطه می‌تونه به خودش FK داشته باشه! 

-- Employee با Boss (مدیر)
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    EmpName VARCHAR(50),
    BossID INT,  -- FK به خودش!
    FOREIGN KEY (BossID) REFERENCES Employee(EmpID)
);

-- نماد:
Employee(EmpID, EmpName, BossID)
         -----           ......
                           ↑
                  FK به خودش!

نکات مهم:

  1. R₁ و R₂ متمایز نیستند (هر دو یکی هستند)
  1. لزوم Rename کلید خارجی:

→ چون Head مجموعه است → نمی‌توان عضو تکراری داشت → مجبوریم EmpID رو به BossID تغییر نام بدیم

  1. درجه رابطه:

→ اگر n درجه داشته باشیم → تعداد دامنه‌ها برابر حداکثر n-1 است → چون یکی تکراری است (EmpID و BossID همان دامنه)

  1. حلقه یا دور (Cycle) ارجاع داریم

→ Employee به خودش اشاره می‌کنه!

گراف ارجاعات (Reference Graph)

نمونه موجودیتی، کلید خارجی داشته باشد که به یک موجودیت دیگر اشاره نماید با فلشی به آن وصل می‌نماییم.

مثال 1: ساده 

City ← S ← SP
       ↑   ↑
       │   │
       P───┘

S: FK به City
SP: FK به S و P

مثال 2: چرخه ارجاع 

┌──────┐
      │      ↓
Emp → Dept
 ↑      │
 └──────┘

→ امکان دارد در این مسیر ارجاع، چرخه به وجود بیاید

مثال 3: خود-ارجاعی 

Employee ─┐
   ↑      │
   └──────┘

→ حلقه یا دور (چرخه ارجاع)

✍️ تمرینات بخش ۴.۲

تمرین 1 (تشریحی):

رابطه Employee: 

Employee(EmpID, SSN, Name, Email, Phone, DeptID)

فرض:

  • EmpID: یکتا
  • SSN (شماره ملی): یکتا
  • Email: یکتا
  • Name: تکراری
  • Phone: تکراری
  • DeptID: FK به Department

سوالات:

  • الف) همه SK‌ها را بنویسید (حداقل 10 تا).
  • ب) همه CK‌ها را پیدا کنید.
  • ج) کدام را PK انتخاب می‌کنید؟ چرا؟
  • د) AK‌ها چه هستند؟
  • ه) FK کدام است؟

تمرین 2 (تستی):

کدام گزینه نادرست است؟ 

الف) هر CK یک SK است.
ب) هر SK یک CK است.
ج) PK نمی‌تواند Null باشد.
د) FK باید به CK یا PK اشاره کند.

تمرین 3 (تحلیلی):

رابطه Enrollment: 

Enrollment(StudentID, CourseID, Semester, Grade)

داده نمونه: 

+-----+-----+----------+-------+
| SID | CID | Semester | Grade |
+-----+-----+----------+-------+
| 100 | 201 | Fall2024 | 18.0  |
| 100 | 202 | Fall2024 | 17.0  |
| 110 | 201 | Fall2024 | 19.5  |
| 100 | 201 | Spring25 | 16.0  |
+-----+-----+----------+-------+

سوالات:

  • الف) آیا {StudentID, CourseID} CK است؟ چرا؟
  • ب) CK این رابطه چیست؟
  • ج) این رابطه تمام‌کلید است؟
  • د) چند FK دارد؟ به کجا اشاره می‌کنند؟

تمرین 4 (طراحی):

سیستم فروشگاه: 

موجودیت‌ها:
- Customer (CustomerID, Name, Phone, Email)
- Product (ProductID, Name, Price, CategoryID)
- Category (CategoryID, CategoryName)
- Order (OrderID, CustomerID, OrderDate, TotalAmount)
- OrderItem (OrderID, ProductID, Quantity, UnitPrice)

طراحی کنید:

  • الف) هر رابطه را با PK و FK مشخص کنید.
  • ب) گراف ارجاعات را رسم کنید.
  • ج) آیا چرخه ارجاعی وجود دارد؟

تمرین 5 (مفهومی):

سؤال 1: چرا می‌گوییم "هر CK یک SK است ولی هر SK یک CK نیست"؟ با مثال کامل توضیح دهید.

سؤال 2: تفاوت کاهش‌پذیری و کاهش‌ناپذیری را با 3 مثال توضیح دهید.

سؤال 3: چرا رابطه تمام‌کلید حداقل در BCNF است؟

تمرین 6 (پیشرفته):

رابطه پیچیده: 

CREATE TABLE Student (
    StudentID INT,
    NationalID VARCHAR(10),
    Name VARCHAR(50),
    FatherName VARCHAR(50),
    BirthYear INT,
    BirthCity VARCHAR(30),
    PRIMARY KEY (StudentID)
);

فرض:

  • StudentID: یکتا
  • NationalID: یکتا
  • (Name, FatherName, BirthYear, BirthCity): یکتا
  • (NationalID, BirthYear): یکتا

سوالات:

  • الف) همه CK‌ها را پیدا کنید و اثبات کنید.
  • ب) آیا {NationalID, BirthYear} CK است؟ چرا؟
  • ج) اگر بخواهیم FK اضافه کنیم (مثلاً CityID)، چه تغییراتی لازم است؟

نکات طلایی:

  • ✅ SK: Uniqueness، 1 تا 2ⁿ-1
  • ✅ CK: SK + Irreducibility، 1 تا n
  • ✅ PK: یکی از CK، NOT NULL، Index اتوماتیک
  • ✅ AK: CK - PK، UNIQUE
  • ✅ FK: اشاره به CK یا PK، ارتباط جداول
  • ✅ تمام‌کلید: CK = H، حداقل BCNF
  • ✅ PK vs UNIQUE: PK فقط 1، UNIQUE چند تا
  • ✅ هر CK یک SK، ولی هر SK یک CK نیست
