🔷 حالت 9: نگاشت صفت مرکب (Composite Attribute)

قاعده

صفت مرکب → تجزیه به اجزا! 

E با صفت مرکب A (A1, A2, A3)
→ جدول E (... A1, A2, A3)

تصمیم‌گیری: آیا اجزا را جدا نگه داریم یا یکجا؟

مثال 1: آدرس (مرکب)

نمودار ER: 

┌──────────┐
│ Employee │
├──────────┤
│ EmpID    │
│ Name     │
│ Address  │ ← مرکب!
│  ├ City  │
│  ├ Street│
│  └ No    │
└──────────┘

نگاشت - روش 1: تجزیه کامل 

CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Name NVARCHAR(50),
    City NVARCHAR(30),  -- جزء 1
    Street NVARCHAR(50),  -- جزء 2
    AddressNo VARCHAR(10)  -- جزء 3
);

-- نماد:
Employee(EmpID, Name, City, Street, AddressNo)

نگاشت - روش 2: یکجا (ساده‌سازی) 

CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Name NVARCHAR(50),
    FullAddress NVARCHAR(200)  -- همه با هم!
);

-- مثلاً: "Tehran, Valiasr St., No. 123"

مقایسه:

معیارتجزیه (روش 1)یکجا (روش 2)
Query روی جزءآسان ✅سخت ❌

Indexingممکن روی Cityغیرممکن
توصیه: همیشه تجزیه کن! ✅

🔷 حالت 10: نگاشت ارتباط 1:1

قاعده

ارتباط 1:1 → 2 یا 3 رابطه 

E1 ──1:1── E2
→ بستگی به مشارکت:
  1. هر دو الزامی → 2 رابطه (Merge یا FK)
  2. یک طرف الزامی → 2 رابطه (FK در الزامی)
  3. هر دو اختیاری → 3 رابطه (جدول ارتباط)

🔷 حالت 11: نگاشت ارتباط n-ary (درجه ≥ 3)

قاعده

ارتباط درجه n → n+1 رابطه 

E1 ──┐
     │
E2 ──┤── R (ارتباط سه‌تایی)
     │
E3 ──┘

→ 4 رابطه: E1, E2, E3, R

PK جدول ارتباط: ترکیب همه FK‌ها (یا بخشی)

مثال 1: فروشنده-قطعه-پروژه (SPJ)

نمودار ER: 

S
       │
       │
  Qty  ├── Supply
       │
       │
   P ──┴── J

نگاشت: 

-- رابطه 1: Supplier
CREATE TABLE S (
    S# INT PRIMARY KEY,
    SName NVARCHAR(50),
    City NVARCHAR(30),
    Status INT
);

-- رابطه 2: Part
CREATE TABLE P (
    P# INT PRIMARY KEY,
    PName NVARCHAR(50),
    Color NVARCHAR(20),
    Weight INT
);

-- رابطه 3: Project
CREATE TABLE J (
    J# INT PRIMARY KEY,
    JName NVARCHAR(50),
    City NVARCHAR(30)
);

-- رابطه 4: Supply (ارتباط 3-تایی)
CREATE TABLE SPJ (
    S# INT,
    P# INT,
    J# INT,
    Qty INT,  -- صفت ارتباط
    PRIMARY KEY (S#, P#, J#),
    FOREIGN KEY (S#) REFERENCES S(S#),
    FOREIGN KEY (P#) REFERENCES P(P#),
    FOREIGN KEY (J#) REFERENCES J(J#)
);

-- نماد:
S(S#, SName, City, Status)
  ---

P(P#, PName, Color, Weight)
  ---

J(J#, JName, City)
  ---

SPJ(S#, P#, J#, Qty)
    --------------
    ↓ PK (3 FK)

داده نمونه: 

S:
+----+-------+--------+--------+
| S# | SName | City   | Status |
+----+-------+--------+--------+
| 10 | Smith | Tehran | 100    |
| 20 | Jones | Shiraz | 200    |
+----+-------+--------+--------+

P:
+----+-------+-------+--------+
| P# | PName | Color | Weight |
+----+-------+-------+--------+
| 1  | Nut   | Red   | 12     |
| 2  | Bolt  | Green | 17     |
+----+-------+-------+--------+

J:
+----+--------+--------+
| J# | JName  | City   |
+----+--------+--------+
| 100| Proj1  | Tehran |
| 200| Proj2  | Mashhad|
+----+--------+--------+

SPJ:
+----+----+-----+-----+
| S# | P# | J#  | Qty |
+----+----+-----+-----+
| 10 | 1  | 100 | 300 |  ← Smith تامین می‌کنه Nut برای Proj1
| 10 | 2  | 100 | 200 |
| 20 | 1  | 200 | 400 |
+----+----+-----+-----+

تحلیل: 

معنا:
→ فروشنده S# قطعه P# را برای پروژه J# تامین می‌کنه
→ (10, 1, 100): Smith, Nut, Proj1 → Qty=300

Query‌ها:
-- قطعات تامین‌شده برای یک پروژه
SELECT P.PName, S.SName, SPJ.Qty
FROM SPJ
JOIN P ON SPJ.P# = P.P#
JOIN S ON SPJ.S# = S.S#
WHERE SPJ.J# = 100;

🔷 حالت 12: نگاشت Is-A (وراثت)

قاعده

ارتباط Is-A با n زیرنوع → راه‌های مختلف: 

E (سوپرکلاس)
     │
     ├── E1 (زیرکلاس 1)
     ├── E2 (زیرکلاس 2)
     └── En (زیرکلاس n)

→ 4 روش نگاشت:
  1. n+1 جدول (جدا)
  2. n جدول (بدون سوپرکلاس)
  3. 1 جدول + Type
  4. 1 جدول + Flag bits

روش 1: n+1 جدول (جدا)

نمودار ER: 

Employee
     /    |    \
   Full Part Contract

نگاشت: 

-- جدول سوپرکلاس
CREATE TABLE Employee (
    EmpID INT PRIMARY KEY,
    Name NVARCHAR(50),
    Age INT
);

-- جدول زیرکلاس 1
CREATE TABLE FullTime (
    EmpID INT PRIMARY KEY,
    Salary DECIMAL(10,2),
    Benefits NVARCHAR(100),
    FOREIGN KEY (EmpID) REFERENCES Employee(EmpID)
);

-- جدول زیرکلاس 2
CREATE TABLE PartTime (
    EmpID INT PRIMARY KEY,
    HourlyRate DECIMAL(10,2),
    MaxHours INT,
    FOREIGN KEY (EmpID) REFERENCES Employee(EmpID)
);

-- جدول زیرکلاس 3
CREATE TABLE Contract (
    EmpID INT PRIMARY KEY,
    ContractDate DATE,
    ContractPeriod INT,
    FOREIGN KEY (EmpID) REFERENCES Employee(EmpID)
);

نکات مهم حالت 12 (Is-A)

✅ نکته 1: روش n+1 معمولاً بهترین است

✅ نکته 2: تخصیص مجزا (Disjoint) یا هم‌پوشان (Overlapping)?

  • مجزا → هر کارمند فقط یک نوع
  • هم‌پوشان → ممکنه چند نوع باشه

✅ نکته 3: تخصیص کامل (Total) یا ناقص (Partial)?

  • کامل → هر کارمند حتماً یک زیرنوع
  • ناقص → ممکنه فقط سوپرکلاس باشه

✅ نکته 4: برای Overlapping → روش Flags

✅ نکته 5: برای Disjoint + Total → روش n

❌ خطا: استفاده از Type با NULL زیاد!

🔷 حالت 13: سلسله‌مراتبی موجودیتی

قاعده

سلسله‌مراتب n سطحی: 

E1 → E2 → E3 → ... → En
→ n جدول + FK سلسله‌مراتبی

FK: پدر به فرزند کلید می‌ده + FK جزو PK فرزند

مثال: گروه آموزشی - استاد - دانشجو

نمودار ER: 

Group → Teacher → Student

نگاشت: 

-- سطح 1: Group
CREATE TABLE AcademicGroup (
    GroupID INT PRIMARY KEY,
    GroupTitle NVARCHAR(50)
);

-- سطح 2: Teacher
CREATE TABLE Teacher (
    TeacherID INT,
    GroupID INT,  -- FK از پدر + جزو PK!
    Name NVARCHAR(50),
    PRIMARY KEY (TeacherID, GroupID),
    FOREIGN KEY (GroupID) REFERENCES AcademicGroup(GroupID)
);

-- سطح 3: Student
CREATE TABLE Student (
    StudentID INT,
    TeacherID INT,  -- FK از پدر + جزو PK!
    GroupID INT,  -- FK از جد + جزو PK!
    Name NVARCHAR(50),
    PRIMARY KEY (StudentID, TeacherID, GroupID),
    FOREIGN KEY (TeacherID, GroupID) REFERENCES Teacher(TeacherID, GroupID)
);

داده نمونه: 

AcademicGroup:
+-----+------------+
| GID | Title      |
+-----+------------+
| 1   | Computer   |
| 2   | Math       |
+-----+------------+

Teacher:
+-----+-----+--------+
| TID | GID | Name   |
+-----+-----+--------+
| 10  | 1   | Dr.A   |
| 20  | 1   | Dr.B   |
| 30  | 2   | Dr.C   |
+-----+-----+--------+

Student:
+-----+-----+-----+--------+
| SID | TID | GID | Name   |
+-----+-----+-----+--------+
| 100 | 10  | 1   | علی    |
| 110 | 10  | 1   | سارا   |
| 120 | 20  | 1   | رضا    |
| 130 | 30  | 2   | مینا   |
+-----+-----+-----+--------+

تحلیل: 

PK های سلسله‌مراتبی:
→ Group: (GroupID)
→ Teacher: (TeacherID, GroupID)
→ Student: (StudentID, TeacherID, GroupID)

FK های سلسله‌مراتبی:
→ Teacher.GroupID → Group.GroupID
→ Student.(TeacherID, GroupID) → Teacher.(TeacherID, GroupID)

مثال 2: استان - شهر - محله

CREATE TABLE Province (
    ProvinceID INT PRIMARY KEY,
    ProvinceName NVARCHAR(50)
);

CREATE TABLE City (
    CityID INT,
    ProvinceID INT,
    CityName NVARCHAR(50),
    PRIMARY KEY (CityID, ProvinceID),
    FOREIGN KEY (ProvinceID) REFERENCES Province(ProvinceID)
);

CREATE TABLE District (
    DistrictID INT,
    CityID INT,
    ProvinceID INT,
    DistrictName NVARCHAR(50),
    PRIMARY KEY (DistrictID, CityID, ProvinceID),
    FOREIGN KEY (CityID, ProvinceID) REFERENCES City(CityID, ProvinceID)
);

معایب روش سلسله‌مراتبی

❌ معایب:

  1. تعداد زیاد کلیدهای خارجی

→ Student دارای 2 FK

  1. طول کلیدها زیاد است

→ PK(Student) = 3 صفت!

  1. تعداد FK: n(n-1)/2

→ برای 5 سطح: 5×4/2 = 10 FK!

  1. کلیدهای داخلی زیاد

→ عملکرد پایین‌تر

نکات مهم حالت 13 (سلسله‌مراتبی)

✅ نکته 2: طول کلید افزایش می‌یابد

✅ نکته 3: CASCADE DELETE ضروری

✅ نکته 4: معمولاً تا 3-4 سطح OK

❌ خطا: سلسله‌مراتب خیلی عمیق (>5)

🔷 حالت 14: چند ارتباط بین دو موجودیت

قاعده

اگر n ارتباط بین E1 و E2: 

→ هر ارتباط جدول جداگانه

مثال: Student و Course

نمودار ER: 

┌─ Enrolls (M:N)
Student ┤
        ├─ TeachingAssist (M:N)
        └─ Tutors (1:N)
Course

نگاشت: 

CREATE TABLE Student (
    StudentID INT PRIMARY KEY,
    Name NVARCHAR(50)
);

CREATE TABLE Course (
    CourseID INT PRIMARY KEY,
    CourseName NVARCHAR(100)
);

-- ارتباط 1: Enrolls
CREATE TABLE Enrollment (
    StudentID INT,
    CourseID INT,
    Semester NVARCHAR(10),
    Grade DECIMAL(4,2),
    PRIMARY KEY (StudentID, CourseID, Semester),
    FOREIGN KEY (StudentID) REFERENCES Student(StudentID),
    FOREIGN KEY (CourseID) REFERENCES Course(CourseID)
);

-- ارتباط 2: TeachingAssist
CREATE TABLE TA (
    StudentID INT,
    CourseID INT,
    Semester NVARCHAR(10),
    Hours INT,
    PRIMARY KEY (StudentID, CourseID, Semester),
    FOREIGN KEY (StudentID) REFERENCES Student(StudentID),
    FOREIGN KEY (CourseID) REFERENCES Course(CourseID)
);

-- ارتباط 3: Tutors
CREATE TABLE Tutoring (
    StudentID INT,
    CourseID INT,
    TutoringDate DATE,
    PRIMARY KEY (StudentID, CourseID, TutoringDate),
    FOREIGN KEY (StudentID) REFERENCES Student(StudentID),
    FOREIGN KEY (CourseID) REFERENCES Course(CourseID)
);

تمرین 1 (تشریحی): سیستم کتابخانه

طراحی نمودار ER و نگاشت به جداول: 

موجودیت‌ها:
- Book (ISBN, Title, Publisher, Year)
- Author (AuthorID, Name, Country, BirthYear)
- Member (MemberID, Name, Phone, {Email})
- Librarian (LibrarianID, Name, Shift)

ارتباطات:
- Book -M:N- Author (نوشته، PublicationYear)
- Member -M:N- Book (استعاره، BorrowDate, ReturnDate)
- Librarian -1:N- Book (مسئول، AssignDate)

انجام دهید:

  • الف) نمودار ER کامل
  • ب) نگاشت به جداول با PK و FK
  • ج) 10 Query مفید
  • د) داده نمونه برای هر جدول

تمرین 2 (تستی):

کدام گزینه نادرست است؟ 

الف) در ارتباط M:N همیشه 3 جدول داریم.
ب) در ارتباط 1:N همیشه طرف N کلید خارجی می‌گیرد.
ج) موجودیت ضعیف همیشه 2 جدول دارد.
د) صفت چندمقداری همیشه در همان جدول می‌ماند.

تمرین 3 (تحلیلی): بیمارستان
