🎯 مقدمه تعاملی

خوب دانشجوی عزیز، در بخش قبل با موجودیت آشنا شدیم. حالا سوال این است: چه چیزهایی رو درباره موجودیت ذخیره کنیم؟ 🤔 

دانشجو:
- نام؟ ✅
- کد دانشجویی؟ ✅

🔑 دسته‌بندی اول: شناسه و ناشناسه

1. صفت شناسه (Identifier / Key Attribute)

تعریف : صفت شناسه: صفتی است که در بین مجموعه نمونه‌های آن موجودیت مقدار منحصر به فرد داشته باشد (Unique). 

graph LR
    A[Student]
    B((StudentID
شناسه - PK))

    A --- B

    style A fill:#3498db,color:#fff
    style B fill:#f39c12,color:#fff,stroke:#000,stroke-width:3px

نماد: بیضی با خط زیر

مثال:

StudentIDNameField
123علیکامپیوتر
124رضابرق
125علیعمران
تحلیل:
  • StudentID: همه مقادیر یکتا ✅ → شناسه
  • Name: "علی" تکرار شده ❌ → ناشناسه
  • Field: منحصر به فرد نیست ❌ → ناشناسه

نکته: چند صفت شناسه

: "یک موجودیت می‌تواند بیش از یک صفت شناسه داشته باشد." 

دانشجو:
- StudentID: 9412345 (یکتا) ✅
- NationalID: 0012345678 (یکتا) ✅
- Email: ali@university.ac.ir (یکتا) ✅

→ دانشجو 3 صفت شناسه داره!

ولی: یک صفت شناسه باید به عنوان صفت شناسه اصلی (Primary Key) انتخاب شود.

ضابطه انتخاب شناسه اصلی ()

: یک صفت شناسه از بین صفات شناسه باید بعنوان صفت شناسه اصلی انتخاب شود:

  • طول کوتاه‌تری داشته باشد
  • در محیط شناخته شده‌تر باشد

مثال:

NationalID10 رقمبلهخوب ✅
Email30+ کاراکترخیرنه ❌
انتخاب: StudentID به عنوان شناسه اصلی ✅

2. صفت ناشناسه (Non-Key Attribute)

تعریف : صفت ناشناسه: صفتی که در نمونه موجودیت‌های یک موجودیت، یکتایی مقدار نداشته باشد. 

Name: علی، رضا، علی، مریم
→ "علی" تکرار شده
→ یکتا نیست ❌
→ ناشناسه است

تعریف : صفت ساده: صفتی است که تجزیه‌ناپذیر باشد (Atomic). اجزایش در محیط معنی نداشته باشد.

💻 دسته‌بندی چهارم: واقعی و مجازی

1. صفت واقعی (Stored Attribute)

تعریف: صفت واقعی: صفتی که مقدارش واقعاً ذخیره می‌شود در پایگاه داده. 

Student:
- Name: "علی احمدی"
  → ذخیره می‌شه در DB ✅
  → صفت واقعی

2. صفت مجازی (Derived / Computed Attribute)

تعریف : مجازی: مقدار این صفت دارد محاسبه شود. خود صفت می‌تواند ذخیره شود یا نشود. 

graph LR
    A[Student]
    B((BirthDate
واقعی))
    C((Age
مجازی
محاسبه از BirthDate))

    A --- B
    A -.- C

    style A fill:#3498db,color:#fff
    style B fill:#2ecc71,color:#fff
    style C fill:#9b59b6,color:#fff,stroke-dasharray: 5 5

نماد: بیضی با خط چین

مثال: 

BirthDate = 1375/03/15 (ذخیره می‌شه)
CurrentDate = 1403/10/01

Age = CurrentDate - BirthDate
    = 1403 - 1375
    = 28 سال

→ Age محاسبه می‌شه (مجازی) ✅

مثال دیگر: 

Table: Products
- Price: 1000 (واقعی)
- Quantity: 50 (واقعی)
- TotalValue: Price × Quantity = 50,000 (مجازی)

چرا مجازی؟

  • جلوگیری از افزونگی ✅
  • همیشه به‌روز است ✅
  • فضای کمتری می‌گیره ✅

ولی:

  • محاسبه برای هر Query (کندتر) ❌

انتخاب: 

اگر خیلی استفاده می‌شه:
→ ذخیره کن (واقعی) ✅

اگر کم استفاده می‌شه:
→ محاسبه کن (مجازی) ✅

تعریف : هیچ‌مقدار پذیر: صفتی که مقدار ناشناخته باشد می‌گوییم هیچ‌مقدار پذیر است.

2. صفت هیچ‌مقدار ناپذیر (Not Nullable)

تعریف: هیچ‌مقدار ناپذیر: صفتی که حتماً باید مقدار داشته باشد. 

Student:
- StudentID: NOT NULL ✅
- Name: NOT NULL ✅
- PhoneNumber: NULLABLE ✓

چرا StudentID نمی‌تونه NULL باشه؟ 

→ چون شناسه است!
→ برای تشخیص دانشجو لازمه!
→ حتماً باید مقدار داشته باشه ✅

نکته مهم: معمولاً صفات شناسه باید NOT NULL باشن!

🎯 دامنه مقادیر (Domain)

تعریف : دامنه مقادیر: نوع صفت و مجموعه مقادیر مجاز برای یک صفت را مشخص می‌نماید.

اجزای دامنه مقادیر

1. نوع (Type): 

StudentID: INTEGER
Name: VARCHAR(50)
BirthDate: DATE
GPA: FLOAT

2. مجموعه مقادیر مجاز:

صفتنوعدامنه مقادیر
AgeINTEGER[18, 100]
GPAFLOAT[0.0, 20.0]
GenderCHAR(1){'M', 'F'}
GradeVARCHAR(1){'A', 'B', 'C', 'D', 'F'}
#### مثال کامل 
صفت: Age (سن)

نوع: INTEGER
دامنه: [0, 150]
مقادیر مجاز: {0, 1, 2, ..., 149, 150}

مقادیر نامعتبر:
- -5 ❌ (منفی!)
- 200 ❌ (خارج از دامنه!)
- "بیست" ❌ (نوع اشتباه!)
- 25.5 ❌ (اعشاری!)

محدودیت‌های دامنه‌ای

: محدودیت دامنه‌ای صفت، مهمترین محدودیت است یعنی نوع آن صفت و مجموعه مقادیرش که در آن دامنه تعریف شده‌اند، تغییر یابند. 

-- تعریف دامنه
CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    Name VARCHAR(50) NOT NULL,
    Age INT CHECK (Age >= 18 AND Age <= 65),
    GPA DECIMAL(4,2) CHECK (GPA >= 0 AND GPA <= 20),
    Gender CHAR(1) CHECK (Gender IN ('M', 'F'))
);

-- مثال‌های ورودی
INSERT INTO Students VALUES (123, 'علی', 20, 17.5, 'M'); -- ✅ معتبر
INSERT INTO Students VALUES (124, 'رضا', 15, 18.0, 'M'); -- ❌ Age < 18
INSERT INTO Students VALUES (125, 'مریم', 22, 25.0, 'F'); -- ❌ GPA > 20
INSERT INTO Students VALUES (126, 'سارا', 25, 19.0, 'X'); -- ❌ Gender نامعتبر

🔧 عملیات روی صفات

نکته : "هر عملیاتی را روی هر صفت نمی‌توان انجام داد."

عملیاتName (STRING)Age (INTEGER)GPA (FLOAT)
جمع (+)❌✅✅
تفریق (-)❌✅✅
ضرب (×)❌✅✅
الحاق (Concat)✅❌❌
مقایسه (>)❌✅✅

مثال: 
-- معتبر ✅
SELECT Age + 5 FROM Students;
SELECT GPA * 1.1 FROM Students;
SELECT CONCAT(FirstName, ' ', LastName) FROM Students;

-- نامعتبر ❌
SELECT Name + Age FROM Students; -- ❌ نوع‌ها سازگار نیستن!
SELECT Name * 2 FROM Students; -- ❌ ضرب STRING؟!
